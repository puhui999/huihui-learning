### 第二晚：Boot 4 差异 + 空项目找手感（~4h）

**读**（1.5h，只看跟自己相关的）：
- [Spring Boot 4.0 Migration Guide](https://github.com/spring-projects/spring-boot/wiki/Spring-Boot-4.0-Migration-Guide)
- [Upgrading to Spring Framework 7.x](https://github.com/spring-projects/spring-framework/wiki/Upgrading-to-Spring-Framework-7.x)

已核实、跟 yudao 那套最相关的变化：
1. **Jackson 3**：groupId 从 `com.fasterxml.jackson` 变 `tools.jackson`，`ObjectMapper` 换成 `tools.jackson.databind.json.JsonMapper`；注解仍是 `com.fasterxml.jackson.annotation`。yudao 的 JsonUtils 那类工具在 Boot 4 要改写。
2. **Starter 改名与拆分**：`spring-boot-starter-web` 改为 `spring-boot-starter-webmvc`；自动配置拆成小模块，用到什么技术必须显式声明对应 starter。
3. **测试切片**按 `spring-boot-starter-<技术>-test` 拆包，`@WebMvcTest` 等要引对应模块。
4. **JSpecify 空安全注解**取代旧的 Spring `@Nullable`，编译期可能报 nullness 警告。
5. **Spring Retry 被 Framework 7 内置 retry 取代**；Spring AI 的 `spring.ai.retry.*` 就建在它上面。
6. **Undertow 支持删除**（Servlet 6.1 基线）；Security 7 合并了 Authorization Server。

**做**（2.5h）：生成项目并写熟悉的东西。仓库先 clone 到 Windows：`git clone git@github.com:puhui999/huihui-learning.git`。

### 第三晚：第一个 ChatClient 调用（~3h）

`src/main/resources/application.yml`：

```yaml
spring:
  application:
    name: demo-00-hello
  ai:
    openai:
      base-url: https://api.deepseek.com
      api-key: ${DEEPSEEK_API_KEY}
      chat:
        model: deepseek-chat
        temperature: 0.7
```

`HelloController.java`：

```java
@RestController
public class HelloController {

    private final ChatClient chatClient;

    public HelloController(ChatClient.Builder builder) {
        this.chatClient = builder.build();
    }

    @GetMapping("/ai/hello")
    public String hello(@RequestParam(defaultValue = "用一句话介绍 Spring AI") String q) {
        return chatClient.prompt().user(q).call().content();
    }
}
```

```powershell
.\mvnw.cmd spring-boot:run
curl.exe -s http://localhost:8080/ai/hello
curl.exe -s "http://localhost:8080/ai/hello?q=Spring%20Boot%204%20相比%203%20最大的变化是什么"
```

## 踩坑预警（写代码前先知道）

- Spring AI 2.0 属性已**扁平化**：是 `spring.ai.openai.chat.model`，不是 1.x 的 `chat.options.model`（旧写法只是 deprecated 兼容）。
- 2.0 的 OpenAI 模块底层换成官方 openai-java SDK，base-url 默认不带 `/v1`，官方文档 DeepSeek 示例就是 `https://api.deepseek.com`。已用假 Key 实测：请求能到达 DeepSeek 并返回 401，说明路径正确，不需要加 `/v1`。
- `setx` 设的变量只对之后新开的进程生效；IDEA 里读不到 Key 就重启 IDEA，或在 Run Configuration 的 Environment variables 里再配一次。
- PowerShell 里 `curl` 可能是 Invoke-WebRequest 的别名，`-d` 参数会报错，统一用 `curl.exe`。
- JDK 24+ 启动时若打印 `sun.misc.Unsafe` 的 terminally deprecated 警告，是某个依赖库的问题，不影响运行。

## 踩坑记录（现象 → 排查 → 根因 → 解决）

_做的过程中随手记，验收时一起 review。_

### 2026-09-03 启动时一串 WARNING：360 安全卫士注入的 Java agent

- **现象**：`mvnw spring-boot:run` 启动时打印 `A Java agent has been loaded dynamically (D:\360Safe\safemon\qhjwsp\bin\qhjwsp-agent-1.0.3.jar)`，随后是 `System::load` 受限方法、`sun.misc.Unsafe::objectFieldOffset` 两组 WARNING，调用方都是 `com.baize.aegis.*`；开头还有一行 CDS "Sharing is only supported for boot loader classes"。
- **排查**：agent 路径在 360Safe 目录下，类名 baize/aegis 与项目无关。退出 360 后重启应用，WARNING 消失即可确认。
- **根因**：360 安全卫士的 Java 应用防护组件通过 attach 机制向本机每个 JVM 动态注入 agent 做字节码织入。JDK 21+ 对动态 agent、受限本地访问、Unsafe 内存访问三类行为默认告警。
- **解决**：只是告警，应用正常。开发机建议在 360 防护设置里关闭该 Java 防护项，或把 JDK / 项目目录加入信任区。只想压掉告警可在 IDEA Run Configuration 的 VM options 加 `-XX:+EnableDynamicAgentLoading --enable-native-access=ALL-UNNAMED --sun-misc-unsafe-memory-access=allow`，治标不治本。
- **彻底去掉（2026-09-03 查证）**：360 社区帖子里官方人员答复"没有办法单独关闭"，建议升级到官网最新版/beta 版（据称已修复）；用户实际做法是卸载 360，或"设置里关闭自我保护后退出 360，删掉 `D:\360Safe\safemon\qhjwsp` 目录"，但 360 更新后可能装回来。开发机首选直接卸载 360，用 Windows Defender 即可。不动 360 的兜底：应用 Run Configuration 加 `-XX:+DisableAttachMechanism` 禁止动态 attach，360 就注不进来；但该参数不能加在测试上，Mockito inline 依赖自附加。
